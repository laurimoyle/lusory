# Invariants (verbatim, project instructions §5)

Attached to every brief. Violations are build failures, not style notes.

- No streaks, scores, badges, stored progress, or user-facing metrics of any kind.
- One player-state fact only: last-open date, for the grasshopper's indifference. During the private beta only, a second device-local boolean may remember that required intake was completed; it contains no email, referral answer, or behavior and disappears from the product when the gate is retired.
- Local-first; no behavioral telemetry or player history. A game choice may increment only an anonymous weekly game/source counter; no raw event or identifier may exist, and aggregate counts may never personalize a shelf.
- Asked, never sensed: during the private beta, email and referral source are required before entry and stored in separate pools with no shared identifier; afterward, email capture returns to optional. Usability answers and explicitly consented testimonials also live in separate pools. No clickstream, session replay, UTM, browser referrer, or fingerprint.
- Difficulty prompt is symmetric (harder/same/gentler), chosen fresh each session, never ranked.
- Grasshopper: max one moment per session (two on introduction day), five sanctioned slots only, never reactive, never in reflection or safety text.
- Content U/PG. Community features physical-only.
- Every feature passes: "Would someone still want this if it forgot they existed for a week?"
